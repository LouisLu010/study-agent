# 知识卡之间的关联单独存一张表，用 ID 指向两头的卡

第十版的知识卡之间有关联（前置、对比、应用，带一句理由）。我们把每条关联存成单独的一条记录：两头知识卡的 ID、种类、理由、是模型提出还是用户添加、用户有没有删过。删过的模型关联不真正删除，只标记，下次整理时模型再提出同一条就忽略。删掉一张知识卡时，App 同时删掉两头带它的关联。

## Considered Options

- 每张知识卡上存一份"我连向谁"的列表：读起来方便，但一条关联只记在一头，另一头不知道；删卡时容易留下指向已删卡片的关联，"用户删过"这种状态也没有地方放。
- SwiftData 的多对多关系：最省代码，但关联本身要带种类、理由和来源，多对多关系放不下；而且 ADR-0004 之后的迁移规则要求关系都是可选的，自引用的多对多在轻量迁移里出问题时很难排查。

## Consequences

- 显示一张卡的关联、画关系图时要按 ID 查一次关联表。一个科目的卡片在几百张以内，一次全部读出来就够了。
- 知识卡和资料一样是独立副本（ADR-0009），删掉原会话不影响知识卡和关联。
