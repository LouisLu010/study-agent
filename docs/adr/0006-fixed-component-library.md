# 交互式回答只用 App 内置的组件库，不让模型写代码

第二版要做类似 ChatGPT Intelligent UI 的交互式回答。我们选择由 App 内置一套固定的组件（参数图像、小测验、分步讲解、几何作图、数据图表），模型只输出组件的描述，由 App 在现有的 WebView 渲染器里（见 ADR-0003）渲染。每个组件沿用 ADR-0002 的写法：一个代码块，语言名是组件种类（`graph`、`geometry`、`chart`、`quiz`、`steps`），内容是 JSON。这和 ChatGPT 的做法一致：它用的是一套原生组件，而不是让模型写代码。主要原因是我们支持任意 OpenAI 兼容模型，而 DeepSeek、通义等模型写出的 HTML/JS 质量不稳定；只输出描述的话，每个模型都能稳定使用，也不需要为模型写的代码做沙盒。代价是只能表达组件库里有的东西。

## Considered Options

- 模型自己写 HTML/JS 小程序，放进沙盒运行（类似 OpenIntelligentUI 和 Claude artifacts）：什么都能做，比如任意物理模拟，但效果依赖模型的写代码能力，还需要一套严格的沙盒（禁止联网、限制计时器、隔离来源）。
- 组件库为主，组件表达不了时允许模型写沙盒代码：功能最全，但要同时维护两套机制。以后要做物理模拟时再考虑。
- 改用原生 SwiftUI 组件：更接近 ChatGPT 的原生体验，但要推翻 ADR-0003，而且公式仍然要靠 WebView 显示。
